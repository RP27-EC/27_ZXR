## 调研：上板(27_ZXR_up) / 下板(27_ZXR) 遥控通信与 IMU（未改代码，用户要求先分析）

### 拨杆与通道事实
- s1/s2 三档值：`RC_SW_UP=1 / RC_SW_MID=3 / RC_SW_DOWN=2`（两边 rc_sensor.h 一致）。
  上板已有宏 `IF_RC_SW1_MID / UP / DOWN` 可直接用。
- 通道别名（上板 rc_sensor.h:77-80）：ch0=右摇杆左右，ch1=右摇杆上下，ch2=左摇杆左右，ch3=左摇杆上下；值域 ±660。
- **下板底盘**：`Chassis.c:219` s1==MID → NORMAL，其它 → SLEEP（下板是中档才动）；
  `Chassis.c:229-231` ch3=前后、ch2=左右、**ch0=底盘旋转 wz**。

### 板间通信（关键限制）
- 下板→上板只有 2 帧（下板 communicate.c:28-46，1ms）：
  0xD1 = ch0~ch3；0xD2 = s1、s2、mouse_vx/vy、key_v。
- **没有** IMU / 底盘 yaw / 云台角上传。上板拿不到底盘姿态。
- 下板有 BMI088+EKF（`QEKF_INS.YawTotalAngle`，单位是**度**，多圈），但只在下板内部用，
  `Chassis_Posture.c` 是死代码（data_update 无调用点）。

### 上板 IMU（可用于将来的陀螺仪模式）
- 上板也有 BMI088，`imu_sensor` 在 device.c:19 初始化、control_task.c:23 更新（1ms）。
- 支持 EKF / Mahony 两套（rp_config 的 IMU_USE_EKF / IMU_USE_MAHONY 切换）。
- `bmi.h:44 gimbal_transform_t gim_trans`（bmi.c:39，arz=90°）——"陀螺仪坐标变换为云台坐标"，
  说明上板 IMU 与云台有固定安装关系，变换后可得到云台姿态角。
- 注意单位：IMU 的 yaw 是**度**，电机 motor_angle 是**弧度**，混用要转换（工程已有 Degree_to_rad）。

### 关键冲突：ch0 被双用（本次核心发现）
- 下板：`chassis.wz = -ch0`（右摇杆左右 → 底盘旋转）。
- 上板：`gimbal.c:331` yaw 也吃 `RC_RIGH_CH_LR_VALUE`(ch0)。
- 后果：推 ch0 时底盘转 + 云台相对底盘也转 = **叠加**，不是"跟随底盘"。

### "机械模式跟随底盘"的实现要点（方案，未落地）
- 机械模式 = 反馈用电机编码器（云台**相对底盘**角）→ 底盘转时云台相对角被锁住、
  被机械带着转 = **天然就是跟随底盘，不需要底盘 yaw 数据**。
- 要做成"纯跟随"而非叠加：机械模式下 **yaw 的遥控输入置 0**（不吃 ch0），
  让 ch0 专供底盘旋转；若还想手动调 yaw，改用下板已上传的 mouse_vx / 键盘，
  或改下板把底盘旋转换到别的通道。
- 拨杆映射建议：s1 中档(3) = 机械模式（与下板"中档底盘才动"一致）；上/下档待定
  （陀螺仪模式 or 卸力）。当前 `GIMB_ENABLE_S1_POS=1` 是"上拨才受控"，需改成中档。
- 模式切换（机械↔陀螺仪）的无扰处理坑：两个坐标系的 target 差一个底盘 yaw，
  切换瞬间必须 `target_angle = 新反馈源读数` + `pid_clear()` 清积分 + 重设 inited，
  否则暴冲；yaw 从"单圈 wrap+err-wrap"切到"IMU 连续角"时 err-wrap 规则也要跟着变。

## 成品代码（hole_infantry）调研结论：IMU 安装位置 + 两套 PID
- 真车路径是 `D:/RMCode/hole_infantry/hole_infantry-hole_infantry_up`（上板 F4 + DM4310 + BMI088）
  与 `..._down`（H7 下板）。
- **IMU 装在云台上（随云台动），不是底盘**：
  - 陀螺仪模式(G_GYRO)外环反馈直接用 `base_info.yaw_imu_angle / pitch_imu_angle`（裸 IMU 角），
    全库没有"IMU角+编码器相对角"合成；机械模式(G_MEC)才用 `*_mec_360_angle`（编码器）。
  - motor_def.h 注释：`gyro_pid //外陀螺仪角度 内陀螺仪速度`，且连机械模式 yaw 内环都喂
    `yaw_imu_speed` —— 只有 IMU 随 yaw 轴转才成立。
  - pitch 限位公式 `IMU_MAX = pitch_imu + (MEC_MAX - pitch_mec)` 只有在 IMU 随 pitch 转时才成立。
  - 全车云台闭环只用上板那块 BMI088（下板 GIMBAL_SWITCH=1 收上板的 yaw_imu）。
  - `gim_trans`（bmi.c / bmi_EKF.c 的 arz/ary/arx，真车 arz=180，本项目 arz=90）只描述
    "IMU 芯片贴片朝向 → 云台正交轴"的常量旋转，与装在哪块结构板无关。
    本项目实际生效的是 EKF 分支，要改朝向请改 `bmi_EKF.c` 的 `EKFgim_trans`，不是 `bmi.c`。
- **两套 PID 是必需的**（成品用 8 个独立 pid_ctrl_t：yaw/pitch × mec/gyro × outer/inner，
  gimbal.h:70-78；按 switch(模式) 换整组 PID 对象，gimbal.c:519-560）。
  pid_conf.h 里的 `*_MACHINE_* / *_GYRO_*` 宏是**死代码**（无 .c 引用），别被误导；
  本项目 pid_conf.h 里那堆同款宏同样是死的。
- 数值规律（参考）：yaw 两模式外环 KP 相同(20)，陀螺仪模式另加 KI=0.05；
  yaw 内环 KP 陀螺仪更小(0.04 vs 0.1)；pitch 两模式内环反馈单位不同（rad/s vs °/s），
  数字不可直接比。**不要预设"陀螺仪模式增益更小"**。
- 切换处理：真车下板把"非当前模式"的 target 每周期打成该模式当前反馈值（切换瞬间误差为 0，
  无跳变）；上板不清积分。本项目以后做陀螺仪模式时建议照搬 + 补 pid_clear。
- 用户问题"当前单独控制云台的 PID 是不是用作机械模式 PID" → **是**，
  两者反馈源都是电机编码器（同一物理量、同一量纲），闭环对象完全相同，
  机械模式只是 yaw 输入置 0，所以当前调好的 PID 直接就是机械模式的参数。
  将来陀螺仪模式要另调一套。

## 简化：删掉 s_last_mode（用户质疑"直接按模式不就好了"）
- 结论：`s_last_mode` 这个额外 static **可以删**，但"每帧只要处于 MECH 就归中"**不行**。
  - 原因：机械模式下 pitch 要正常受控（吃 ch1）。若每帧执行 `pitch.target = LEVEL_ANGLE`，
    pitch 会被永久钉死在水平、摇杆失效。归中必须只发生在"切入那一帧"。
  - 正确的"直接按模式"写法：赋值前的 `g_gimbal_mode` 本身就是上一帧模式，
    直接比较即可检测边沿，不需要额外变量：
    ```c
    next_mode  = sw_mech ? GIMB_MODE_MECH : GIMB_MODE_NORMAL;
    enter_mech = ((next_mode == GIMB_MODE_MECH) && (g_gimbal_mode != GIMB_MODE_MECH));
    g_gimbal_mode = next_mode;
    ```
- 已删除：文件级 `static gimbal_mode_t s_last_mode` 定义、SLEEP 分支里的 `s_last_mode` 同步、
  赋值语句 `s_last_mode = next_mode;`。grep 确认 0 残留。
- 保留：`enter_mech` 局部变量 + `from_sleep || enter_mech` 归中条件 + 归中时 pid_clear。

## 再改：对称版归中（用户要求"两个模式进入时都归中"）
- 原方案只检测 `enter_mech`，导致 **中档 -> 上档（切回单控）不归中**（不对称）。
- 改为通用边沿 `mode_changed = (next_mode != g_gimbal_mode)`，归中条件改成 `if (mode_changed)`：

  - `from_sleep ⇒ mode_changed` 恒成立（SLEEP 不等于任何受控模式），故 `from_sleep ||` 可省（已省）。
  - 模式内持续运行 `mode_changed=0`，不会重复归中（否则 pitch 会被钉死在水平）。

## 最终简化：删除 from_sleep 变量
- `from_sleep` 当初存在，是因为归中块在 `g_gimbal_mode` 被覆盖**之后**执行，需保存"刚才是不是 SLEEP"。
  改成 `mode_changed`（覆盖**之前**计算）后该理由消失；它只剩"从 SLEEP 恢复前要求摇杆回中"一个用途，
  而该判断处 `g_gimbal_mode` 尚未被 next_mode 覆盖、本身就是上一帧模式，
  故直接写 `if (g_gimbal_mode == GIMB_MODE_SLEEP)` 等价且更短。
- 已删除声明与赋值（grep 0 残留），括号平衡 39/39。
- Gimbal_Ctrl 现有局部变量：rc_ok / motor_ok / sw_rc / sw_mech / sw_on / yaw_rc / next_mode / mode_changed。
- 归中逻辑最终形态：`mode_changed = (next_mode != g_gimbal_mode); g_gimbal_mode = next_mode;`
  → `if (mode_changed) { pid_clear x4; pitch.target=LEVEL; yaw.target=CENTER; inited=1; }`。
