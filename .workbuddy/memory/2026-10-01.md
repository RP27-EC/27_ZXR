`HardwareLayer/RM_motor.c`、 `ProtocolLayer/can_protocol.c`、`TaskLayer/control_task.c`。

定位到的问题（按排查优先级）：

1. **旋转项系数量纲错误**（Chassis.c:172-175）
   写成 `wz * WHEEL_RADIUS(0.0515)`，正确应为 `wz * (半轴距 + 半轮距)` =
   `Car_Length/2 + Car_Width/2 = 0.169 + 0.150 = 0.319 m`。差 6.2 倍。
   四个轮的 vx/vy 符号本身是自洽的标准麦克纳姆格式（LF/RB = vx−vy，RF/LB = vx+vy）。
2. **目标速度单位换算反了**：`(vx ± ...)/WHEEL_RADIUS/WHEEL_REDUCT_RATIO` 应是 **乘**
   减速比（若真有 7:1）；若是直驱则根本不该除。当前满杆目标仅 6.94 rad/s。
3. **缺每个轮的方向符号**：config_chassis.h 里 `L_F_Direction/R_F_Direction/...`
   （左 +1、右 −1）定义了但 Chassis.c 完全没用；左右电机镜像安装时必须逐路取反。
4. **CAN ID 与物理角位映射待验证**：LF→201、LB→202、RF→203、RB→204（rxId 0/1/2/3）。
   需确认电调实物 ID 的分配（常见默认 LF/RF/LB/RB = 1/2/3/4，会与之不符）。
5. `Group_Motor_Sleep()` 只把 torque 置 0，不发送 CAN → 失控保护没真正生效。
6. PID 结构体 `.a`（微分低通系数）未初始化且 `last_dout` 从不赋值 → D 项恒为 0。
7. 逐轮独立限幅 `MAX_WHEEL_SPEED_RAD` 会破坏合成方向，应整体等比缩放。
8. 遥控通道无死区；`MAX_SPIN_SPEED 13 rad/s` 相对 (a+b)=0.319 偏大。

参考速查：M3508 输出轴极限约 45~49 rad/s。

## 第七轮：疯车（失控）风险评估 —— 发现一处真实致命隐患

**不会疯车的部分（已逐条核验）**：
- 正反馈风险：无。target 已含极性(±)，measure 用 `rx_info->speed` 原始值，

  电机掉线整车 sleep、上电默认 SLEEP。

**真实致命隐患（唯一一处）**：`Chassis_Step` 的 `!rc_ok || !motor_ok` 分支里，
`group_set_torque()` 被包在 `if (chassis.mode != CHASSIS_MODE_SLEEP)` 内，
只有状态切换那一拍会发 0，之后每拍 `return` 前都不发报文。
而 `Group_Motor_Sleep()` **只把结构体 torque 置 0，不发 CAN** → 电调保持上一条电流。
**已查 C620 手册 p.29-30「异常状态」表，其中没有"CAN 通信中断/超时"这一项，
不能指望电调自动停机。** 场景：满杆前进时遥控器断电 → 车按最后一条电流继续全速冲。
修法：把 `group_set_torque()` 移出 if，每拍都发。

其他参数：遥控离线阈值 60 ms（rc_sensor.c:37），心跳任务 1 ms。

## 第十轮：单位换算体系（已给用户讲解，附经验判据）

三层尺子：RPM（电调报的转子转速）→ rad/s → m/s。
四个换算常数：
- **9.549** = 60/2π，rpm ↔ rad/s
- **19**（3591/187≈19.2）转子 → 输出轴
- **R**（轮半径）轮毂 rad/s ↔ 线速度 m/s
- **a+b**（旋转臂）把车身 yaw 角速度 rad/s 变成轮端线速度 m/s

给定链：ch÷660×MAX_SPEED → 逆解算(vx±vy±wz·(a+b)) → ÷R → ×外部减速比 → PID target
反馈链：CAN DATA[2][3] 转子 rpm → ÷9.549 → ÷19 → PID measure（rx_info->speed）
两条链在【电机输出轴 rad/s】相遇。

若只有 ±400~500 → 报的是输出轴 rpm，此时 `_3508_REDUCT_RATIO` 应设为 1。

真车与培训车量纲不同：真车不做 ÷R，`front/left/cycle` 直接是轮 rad/s；
培训车做 ÷R，`MAX_SPEED` 是 m/s。两边速度上限数字不可直接比较。
