- `K = 4.2072`，`B = -2.496`

本机处理：
- 已在 `config_gimbal.h` 把 `GIMB_PITCH_GRAV_K/B` 设为真车参考值(4.2072 / -2.496)，
  并注释说明 K/B 幅值可借作起点；`GIMB_PITCH_GRAV_CENTER` 仍为 0，**必须本机标定**

结论：重力前馈方案与文档(5.1.2云台)、真车三方一致，无需改算法，只差本机标定 θc 与微调 K/B。

## 云台零位偏移（确定"水平=控制零位"）已落地
用户指出：pitch 上电不在水平时，当前代码(无偏移)无法把它拉回水平——因为
`motor_angle_sum` 从上电姿态起算=0，"零位"被隐式绑死在上电姿态。

方案（做法B，已落地 config_gimbal.h + gimbal.c）：
- 新增 `GIMB_PITCH_ZERO_OFFSET` / `GIMB_YAW_ZERO_OFFSET` 宏，运行期全局
  `g_axis_zero_offset[]`，真实控制角 = `motor_angle_sum - 该偏移`，使"水平恒为 0"，与上电姿态解耦。
- 新增 `Gimbal_Real_Angle(axis)` 辅助：所有角度相关运算(目标对齐、角度环反馈、
  重力前馈θ)统一改用它，替代裸 `motor_angle_sum`。
- 新增 `Gimbal_Calibrate_Zero(idx)`：调试期把"当前姿态"即时设为零位（无需重编译）。
- 标定步骤：云台摆水平 → 读 Pitch 电机 `motor_angle_sum`(Keil Watch/调试打印) →
  填 `GIMB_PITCH_ZERO_OFFSET`(Yaw 同理填中位时的 sum)。

附带修复：归中块里 `target=LEVEL_ANGLE` 后必须 `inited=1`，否则本帧
`Target_Update`(!inited) 会把 target 覆盖回实际角，导致上电回中失效（原有隐患）。

(`gimbal.h:13-14`)：`PITCH_MOTOR_ANGLE_MIDDLE=2.59309077f`、
`YAW_MOTOR_ANGLE_MIDDLE=-0.387884378f`，均为该机机械参考姿态时的单圈角 `motor_angle`。

处理：本机 `GIMB_*_ZERO_OFFSET` 机制已与真车 `*_MIDDLE` 等价（把机械水平/中位钉为
控制角 0），但**真车数值不能直接抄**——真车用单圈 `motor_angle`(相对编码器零点)，
本机用多圈 `motor_angle_sum`(上电起算)，角帧/电机零点不同。已把真车值作为注释锚点
写进 `config_gimbal.h`，并在宏旁给出"若本机零点已与真车对齐可直接用"的取消注释版，
初值保持 0（本机安全默认=上电零位即控制零位）。

注意：真车 yaw 上电强制归中到 MIDDLE(≈-22°)；本机 yaw 当前无强制归中(靠 RC 积分，
上电对齐反馈)，若需严格照真车"上电归中到中位"需另加逻辑（本机 offset 后中位=0）。

## 云台角度反馈由多圈改为单圈（与真车同帧，直接采用真车零位值）
用户要求"改成单圈，毕竟同一台车零位点都一样"。确认 `single_pid_ctrl()`(PID.c:9)
内部 `pid->err=...` 已被注释，err 由外部计算 → 可在外做 err-wrap 不会被覆盖。

改动（gimbal.c + config_gimbal.h）：
- `Gimbal_Real_Angle()` 改用单圈 `motor_angle`（不再用 `motor_angle_sum`），
  真实控制角 = `motor_angle - g_axis_zero_offset[idx]`。
- 角度环 err 增加最短路径 wrap：`err>π 则 -2π；err<-π 则 +2π`，
  这是单圈不暴冲的关键保险（跨越 ±π 边界时不会算出≈2π 反向误差）。
- `Gimbal_Calibrate_Zero()` 运行期标定也改用 `motor_angle`。
- `config_gimbal.h`：`GIMB_PITCH_ZERO_OFFSET=2.59309077f`、
  `GIMB_YAW_ZERO_OFFSET=-0.387884378f`（真车同值，同车同编码器零点可直接用）；
  `GIMB_PITCH_GRAV_CENTER=0.0856f`（真车 middle_angle，同车同帧直接采用，无需本机重标）。
- 顶部加 `GIMB_PI` 常量（<math.h> M_PI 不可用时兜底）。

前提/风险：数值有效的前提是"同一台车、编码器 zero_position 与真车一致"。
若日后换电机/重刷零点导致偏移变化，改宏或调 `Gimbal_Calibrate_Zero()` 即可。
另：本机 pitch/yaw 软限位仍 = ±π，单圈+err-wrap 下安全，但 pitch 实际行程远小于 π，
装机后可按真实机械行程收紧 `GIMB_PITCH_ANGLE_MAX`。

## Yaw/Pitch 遥控方向翻转旋钮（GIMB_*_RC_DIR）
用户问"摇杆往左为逆时针，yaw 要不要反转符号"。结论：需不需要反转由
① 遥控 ch0 极性(遥控器配置，下板板间通信转发，代码定不了) ② 电机正角度物理方向(安装定)
共同决定，纯代码无法断定，须上电实测。

落地（config_gimbal.h + gimbal.c:322-323）：
- 新增 `GIMB_YAW_RC_DIR=1` / `GIMB_PITCH_RC_DIR=1`（默认不翻转）。
- 用法：`RC_Normalize((int16_t)(GIMB_YAW_RC_DIR * RC_RIGH_CH_LR_VALUE))` 等。
- 若"摇杆往左，Yaw 云台不是逆时针"→ 把 `GIMB_YAW_RC_DIR` 改成 -1。
- 只翻转【遥控输入极性】，不动 `motor_angle`/`speed` 反馈、零位偏移、重力前馈，安全可逆。
- 不推荐动 `motor.c` 的 `order_correction`（会牵连角度+速度反馈符号与零位语义）。
- 真车 pitch/yaw 在 PID 输出层都乘 -1，但那针对【它自己】的遥控极性；本机 ch0 极性
  来自下板板间通信，可能不同，故不能直接抄真车 -1，用 RC_DIR 单独标定。
